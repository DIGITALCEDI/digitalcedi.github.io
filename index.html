I. ПОЛУЧЕНИЕ CID ИЗ ЛЮБОГО БРАУЗЕРА
Публичные шлюзы (ipfs.io) Бесплатный доступ «из коробки» через HTTPS gateway Низкая (общая нагрузка, точки отказа) 🟡 Средняя (кеш зависит от популярности) 🔒 Низкая (полное доверие оператору) Низкая Только тесты / прототипы
Cloudflare IPFS gateway Глобальная CDN, высокая производительность Высокая (регистрация, но стабильно) Очень высокая 🔒 Низкая (централизация) Низкая Быстрый доступ к публичным данным
Trustless gateway (w3s.link) Клиент проверяет хэш — исключает подмену от шлюза Очень высокая (верификация на клиенте) Высокая (range-запросы) 🔒 Высокая (криптографическая проверка) Средняя Production
Service Worker шлюз (inbrowser.link) P2P напрямую из браузера без центрального сервера Высокая (устойчив к цензуре) Высокая (бенчмарки ProbeLab) 🔒 Очень высокая (нет посредника) Высокая Максимальная децентрализация
ipfs-smart-gateway Автоматический failover + выбор быстрейшего шлюза Очень высокая (отказоустойчивость) 🚀 Максимальная 🔒 Низкая (зависит от выбранного шлюза) Средняя Для продакшна, где критична скорость
II. СОХРАНЕНИЕ CID (пининг, долговременность)
Пиннинг‑сервисы (Pinata, Lighthouse) Провайдер хранит данные на своих узлах IPFS Высокая (SLA, но централизация) 💰 Низкие затраты (есть бесплатный тариф) 🔒 Средняя (доверие провайдеру) Низкая Старт проектов, малые объёмы
IPFS Cluster Собственная сеть узлов с репликацией 🚀 Очень высокая (полный контроль) 💸 Высокие (обслуживание серверов) 🔒 Высокая (ваши ключи) Высокая Enterprise, uptime 99.99%
Filecoin (блокчейн-контракты) Экономическое стимулирование майнеров хранить данные Очень высокая (много независимых узлов) 💰💰 Высокие (плата за хранение + retrieval) 🔒 Высокая (криптоэкономика) Высокая Архивы, долгосрок >5 лет
Локальное хранилище +
CID в JSON / SQLite		 Храните хэши только у себя на диске Низкая (единая точка отказа) 🟢 Нулевые (локально) 🔒 Средняя (зависит от шифрования диска) Низкая Только для личного использования
III. ПОСТКВАНТОВАЯ УСТОЙЧИВОСТЬ (PQC) ДЛЯ CID/IPNS
Постквантовые подписи в IPNS
(CRYSTALS-Dilithium, SPHINCS+)		 Защита mapping «IPNS → CID» от квантовых атак на подписи Высокая (устойчивость к QC) 📉 Низкая скорость, большой размер подписи 🔒 Высокая (будущее) Высокая (интеграция) Для данных с длительным сроком жизни (>10 лет)
Гибридные схемы (PQC + классика) Одновременная верификация Ed25519 + PQC (плавный переход) Очень высокая (обратная совместимость) 🟡 Средняя (накладные расходы выше классики) 🔒 Высокая (защита на сегодня + завтра) Высокая Прагматичный выбор
Блокчейн на хэш-подписях (например, QRL) Регистрация CID в блокчейне, устойчивом к квантовым атакам (Winternitz, XMSS) Максимальная (математически доказано) 🔴 Низкая пропускная способность, высокий объём 🔒 Квантово-безопасно Очень высокая Специфичные квантово-защищённые реестры
Обычный блокчейн (Ethereum, Solana) — без PQC Хранение CID в смарт-контракте (подвержено Shor/Algoritm) Высокая (сегодня),
но 0 после QC		 💰💰 Затраты на газ, средняя скорость 🔻 Уязвим (ECDSA/Ed25519) Средняя Только если миграция возможна до эры QC
«Холодное» локальное хранилище (офлайн) CID записан на бумаге/носителе, никакой сети и криптографии Абсолютная (физическая) 🐢 Низкая (ручной ввод) 🔒 Идеальная (без атак) Низкая (для одиночных хэшей) Мастер-ключи, архивные бэкапы
